# Spec Delta

## Purpose

让实现公共固件契约的新上电设备（首期 BL616CL 与 BL618）在局域网内自动找到服务端并取得 MQTT broker 连接参数，替代手工配置 broker 地址的过程。

## ADDED Requirements

### Requirement: 设备广播发现请求

设备在 WiFi 连接成功后，必须（SHALL）向局域网 UDP 发现端口 37020 广播发现请求，直到收到有效响应或达到重试上限。请求必须携带协议版本、设备 ID、设备型号、固件版本和一个随机 nonce；前 30 次发送的相邻间隔为 2 秒加 [0, 250] 毫秒非负随机抖动，连续失败 30 次后改为 30 秒加同样范围抖动；一次会话仅有一个未完成请求，前一次 2 秒响应窗口关闭后才可发送新 nonce，不允许负抖动提前替换。

#### Scenario: 入网后开始发现

- **WHEN** 设备成功连接到 WiFi 且本地没有有效的 broker 配置
- **THEN** 设备在 5 秒内开始向 UDP 37020 端口广播发现请求，且请求中包含设备 ID、型号、固件版本和 nonce

#### Scenario: 持续失败后降频重试

- **WHEN** 设备连续广播 30 次仍未收到有效响应
- **THEN** 设备将广播间隔调整为 30 秒加 [0, 250] 毫秒抖动，并继续发送发现请求

### Requirement: 服务端单播返回 broker 配置

服务端必须（SHALL）监听 UDP 37020 端口；收到格式合法且协议主版本兼容的发现请求后，必须向请求的源 IP 和源端口单播响应。响应必须回显请求中的 nonce，并携带 broker 主机名或 IP、broker 端口、MQTT 协议版本 5、可选用户名与密码、以及配置有效期（秒）。MVP 阶段用户名和密码为空，明文传输。

#### Scenario: 合法请求得到响应

- **WHEN** 服务端收到包含有效设备 ID 和兼容协议版本的发现请求
- **THEN** 服务端向该请求的源地址单播响应，响应中的 nonce 与请求一致，且包含 broker 地址、端口和有效期

#### Scenario: 非法请求被忽略

- **WHEN** 服务端收到缺少设备 ID、字段格式错误或主版本不兼容的发现请求
- **THEN** 服务端不发送任何响应，并记录一条可诊断的日志

### Requirement: 设备校验并采用首个有效响应

设备必须（SHALL）校验响应的 nonce 与当前未完成请求一致、主版本兼容、broker 地址和端口合法。每次发送使用新的随机 nonce，只接受当前请求发送后 2 秒内的响应；成功采用后结束会话，任何迟到或重复响应一律丢弃，不因经过 10 秒而再次接受。校验失败的响应必须被丢弃且不改变现有配置。

#### Scenario: 首个有效响应生效

- **WHEN** 设备在发现会话中收到一个 nonce 匹配且字段合法的响应
- **THEN** 设备立即停止广播，采用该响应中的 broker 配置，结束该发现会话并丢弃其后所有重复或迟到响应

#### Scenario: 伪造或过期响应被拒绝

- **WHEN** 设备收到 nonce 不匹配或主版本不兼容的响应
- **THEN** 设备丢弃该响应，保留原有配置并继续发现流程

### Requirement: 配置持久化与失效重发现

设备必须（SHALL）将 broker 配置、配置格式版本、签发时长 ttl、接收时刻和网络指纹持久化到非易失存储。运行期间用单调时钟计算有效期；有可信跨重启时钟时可重用未到期配置，没有可信时钟时缓存只能作为候选、必须先重新发现确认，禁止把重启当作续期。网络指纹为 SSID、IPv4 子网地址和掩码，不因同一子网内 DHCP 主机地址变化而失效。配置过期、连接连续失败 10 次或网络指纹变化时必须将旧配置标记失效并重发现；若到期前未成功续租，现有 MQTT 连接也必须有界主动下线并关闭，不能无限继续使用过期配置；新配置验证并原子落盘前不破坏旧存储副本，但不得继续把它作为有效配置使用。

#### Scenario: 重启后直接连接

- **WHEN** 设备重启、有可信跨重启时钟证明持久化 broker 配置未到期，且网络指纹未变化
- **THEN** 设备跳过发现流程，直接使用该配置连接 broker

#### Scenario: 配置过期后重新发现

- **WHEN** 持久化的 broker 配置未能续租而超过有效期，或 broker 连接连续失败 10 次
- **THEN** 设备标记旧配置失效并重新广播发现请求；新配置原子提交前保留旧存储副本，但不再用其建立连接

### Requirement: 发现协议版本兼容

发现请求和响应都必须（SHALL）携带主版本号。接收方必须（SHALL）忽略主版本不兼容的消息；对于主版本相同、仅包含未知字段的消息，接收方必须忽略未知字段并继续处理。MVP 使用主版本 1。

#### Scenario: 未知次版本字段被忽略

- **WHEN** 设备收到主版本为 1 但包含未知字段的响应
- **THEN** 设备忽略未知字段并正常采用其中已知的 broker 配置

#### Scenario: 主版本不兼容

- **WHEN** 任一方收到主版本不是 1 的发现消息
- **THEN** 接收方丢弃该消息，不发送响应也不修改本地配置

### Requirement: 发现报文与网络部署边界

发现报文必须（SHALL）为单个不超过 512 字节的 UTF-8 JSON 数据报。请求字段为 `v: 1`、`type: "discover"`、`device_id`、`model`、`fw`、`nonce`；device_id 匹配 `[a-z0-9][a-z0-9-]{0,63}`，model/fw 分别为 1–64 字节字符串，nonce 为随机 16 字节的小写十六进制编码（32 字符）。响应为 `v: 1`、`type: "offer"`、相同 nonce 和 broker 对象；broker 包含 host、port、mqtt_version、username、password、ttl，其中 port 为 1–65535 整数、mqtt_version 必须为 5、ttl 为 60–86400 秒整数（默认 3600），MVP 凭据为空。host 为可从设备访问的 IPv4 地址或不超过 253 字节的 DNS 主机名，不接受 URL、通配地址、回环、多播或广播地址。未知字段仍计入报文大小。畸形、超长或截断数据报一律丢弃。完整合法性以序列化后 512 字节上限为准，各字段分别满足长度约束不代表组合后一定可发送；服务端启动时必须校验配置生成的 offer 能放入该上限。DNS 主机名解析所得地址也必须通过地址检查，解析失败不能被当作有效连接。

服务端必须可显式配置 advertise_host。自动探测仅在唯一可用 LAN IPv4 地址时采用；多网卡有歧义时必须拒绝启用发现并提示配置，不得下发默认路由地址后宣称一定可达。MVP 服务端原生运行于与设备同一可广播子网，broker 可用 Docker bridge 加端口映射；若服务端容器化，必须在受支持平台使用 host networking 或明确的广播转发配置，单纯映射 UDP 端口不保证收到 LAN 广播。发现不是 WiFi 配网：设备必须事先持有 WiFi 凭据。

服务端每来源 IP 每秒最多处理 5 个发现请求（突发 10），全局每秒最多 100 个（突发 200）；来源桶有界且过期回收。超额请求丢弃，日志采样，不为每次丢弃写一条日志。此机制不提供身份认证或抵御不可信网络攻击的保证。

#### Scenario: 缺少跨重启时钟

- **WHEN** 冷启动读取到配置，但无法证明 ttl 尚未到期
- **THEN** 设备重新发现，不直接认为缓存仍有效

#### Scenario: 多网卡未配置地址

- **WHEN** 服务端存在多个候选 LAN IPv4 地址且未配置 advertise_host
- **THEN** 发现功能报告配置错误，不返回可能错误的 broker 地址

#### Scenario: 已连接期间配置过期

- **WHEN** 设备仍连接 MQTT，但后台续租未成功且当前 broker 配置的 ttl 已到期
- **THEN** 设备有界主动下线、停止接受旧连接操作并重新发现，不将现有连接当作配置自动续期

#### Scenario: 重复响应超过十秒

- **WHEN** 某次发现已成功，20 秒后再次收到该 nonce 的 offer
- **THEN** 设备丢弃该响应，不覆盖当前配置

### Requirement: 到期前后台续租

设备必须（SHALL）在每次有效 offer 接收时启动租约计时，并在经过 ttl 的 80% 加 [0, ttl 的 5%] 非负随机抖动时开始后台发现续租，继续使用当前未过期配置和 MQTT 连接。续租使用相同报文、新 nonce、2 秒窗口和发现重试规则；只有当前续租请求对应的合法 offer 才能延长租约。每次重试、成功 MQTT 通信或设备重启本身都不得延长有效期。续租失败且旧租约尚有效时保持连接；到期仍失败则停止接收新操作，按 mqtt-messaging 的主动下线时限关闭连接并继续发现。

合法 offer 的 host（DNS 名大小写规范化后比较）、port、mqtt_version 和凭据与现有配置相同时，只有在旧租约截止时间之前完成原子提交并在运行时状态机确认生效，才可更新 ttl/接收时刻和续租计时而不重连 MQTT、不改变 connection_id、不撤下动态工具。offer 改变连接参数时，先原子保存新配置，再停止接收旧连接新操作，使已在执行的 Handler 在原有至多 3 秒边界内结束，主动下线旧连接并用新 connection_id 连接新 broker。配置提交失败不得延长内存租约或切换连接，仍服从旧截止时间。成功续租不得导致每次循环写 flash，存储适配必须评估实际续租频率下的磨损。续租不是认证，沿用 MVP 可信网络边界。

租约更新与到期必须在同一状态机串行裁决：每次处理提交完成或接受新操作前读取单调时钟，`now >= old_expires_at` 时到期优先（相等也视为到期），不能因 timer 回调延迟或 flash 写入阻塞跳过截止时间。配置写入不得阻塞到期处理；从写任务返回成功不等于已在截止前完成运行时生效。一旦旧租约到期/主动下线已经生效，迟到提交不得撤销该状态或恢复旧 connection_id；停止接收新操作，按既定主动下线时限关闭旧连接，已提交硬件操作可能已执行，不声称能回滚。

新的租约截止时间始终是该合法 offer 的接收时刻加 ttl，不能从提交完成时刻重新计时。迟到提交仅当仍属于当前配置/网络代次、未被更新配置或 factory_reset 替代且新租约尚有效时可用作新连接配置；必须完成旧连接关闭并生成新的 connection_id，经订阅/online/describe 重新确认。无效/已过期的迟到提交不得启用，继续发现；同一配置提交串行化并验证代次，不能由旧写任务覆盖较新的已提交配置。若可用配置提交完成时已达到其续租触发点，则立即调度续租而非另等完整 80% ttl。以上优先级同时适用于相同 broker 续租和切换 broker 的 offer。

#### Scenario: 健康连接无缝续租

- **WHEN** 默认 3600 秒租约在接收后 2880–3060 秒发起续租，收到相同 broker 参数的合法 offer，且存储提交和运行时生效均在旧租约截止前完成
- **THEN** 设备更新租约而不重连 MQTT，connection_id 和已发布动态工具保持不变

#### Scenario: 续租暂时失败

- **WHEN** 后台续租没有得到有效响应，但旧租约尚未到期
- **THEN** 设备继续使用现有连接并重试发现，不因一次失败撤下能力，也不延长旧租约

#### Scenario: 新 nonce 不提前覆盖旧窗口

- **WHEN** 前一次 discover 发出后 1.9 秒收到合法 offer
- **THEN** 该请求的 nonce 仍有效，设备接受响应，不因负抖动提前重发而丢弃

#### Scenario: 续租配置写入失败

- **WHEN** 新 offer 合法但配置原子提交失败
- **THEN** 设备保留旧副本和旧截止时间，不宣称续租成功；旧租约到期后按失效流程下线

#### Scenario: 提交跨越旧租约截止时间

- **WHEN** 旧租约在第 60 秒到期，第 59.9 秒收到相同配置 offer、ttl 为 60 秒，而提交在第 60.2 秒才确认完成
- **THEN** 旧连接按第 60 秒到期流程关闭，不因提交成功恢复；新配置若代次仍有效则截止为第 119.9 秒，使用新 connection_id 连接，而不是延长到第 120.2 秒

#### Scenario: 截止时刻恰好完成提交

- **WHEN** 提交完成的运行时裁决时刻等于旧租约截止时间，或到期 timer 尚未处理但单调时钟已越过截止时间
- **THEN** 到期优先，不再以旧租约接受新操作，也不允许无缝保留旧连接

#### Scenario: 迟到提交已被重置淘汰

- **WHEN** 配置写任务尚未完成时用户执行 factory_reset，使配置代次失效
- **THEN** 旧写任务完成后不得启用该配置或覆盖重置后的有效存储状态
